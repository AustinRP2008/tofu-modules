# tofu-modules

Opinionated OpenTofu modules that sit behind the self-service skills in
[platform-skills](https://github.com/AustinRP2008/platform-skills). Requesters never call these directly:
the `requesting-k8s-cluster` skill turns a small ClusterRequest file into module inputs and fills in
every platform default (network, encryption, private endpoints, logging).

| Module | What it builds | Requester-facing knobs |
|---|---|---|
| [`gke-cluster`](modules/gke-cluster) | GKE Autopilot or Standard, private nodes, Dataplane V2, workload identity | `mode`, `size` (S/M/L), `region`, `release_channel` |
| [`eks-cluster`](modules/eks-cluster) | EKS Auto Mode or managed node group, private endpoint, KMS secrets encryption, API auth mode | `compute_mode`, `size` (S/M/L), `kubernetes_version` |

## Practice setup: nothing is ever applied
Every test runs `tofu test` with `mock_provider` and `command = plan`, so it needs no cloud account,
no credentials and costs nothing. A green test proves the module's logic (sizing maps, mode switches,
validation rules, labels) is right; it does not prove the cloud API will accept the plan.

```bash
mise install                       # opentofu, tflint
cd modules/gke-cluster
tofu init -backend=false && tofu test
```

## Versioning
Consumers pin a tag:
`source = "git::https://github.com/AustinRP2008/tofu-modules.git//modules/gke-cluster?ref=v0.1.0"`.
Breaking input changes bump the minor version while on 0.x.

## CI
Generated by the `onboarding-repo-ci` skill: `.github/workflows/platform.yml` calls the platform's
reusable `tofu` workflow (fmt, validate, tflint, `tofu test`) pinned to a platform-skills commit.
